# Papillae Annotator

魚類の頭部sensory papillaeと解剖学的ランドマークを、画像上で手動記録する日本語Webアプリです。React / TypeScript / Vite / react-konva / Dexieを使用。画像と研究データを外部へ送信せず、ブラウザ内で保存します。

## 起動

Node.js 22.12以上（または20.19以上）とnpmを用意し、このフォルダーで実行します。

```sh
npm install
npm run dev
```

画面に表示された `http://127.0.0.1:5173` をChrome/Edge/Firefoxの最新版で開きます。開発用のローカルサーバーです。`index.html` を直接ダブルクリックする方式には対応しません。pnpmを使用する場合は `pnpm install`, `pnpm dev` も利用できます（依存固定はpnpm-lock.yaml）。

Windows用に `start.bat` も用意しています。依存パッケージが未インストールの場合は最初にインストールし、開発サーバーを起動します。npmがないCodex実行環境ではpnpmを使います。

```sh
npm run build       # TypeScript型検査 + dist/生成
npm run preview     # ビルド済みアプリをローカル表示
npm test            # ドメイン・IndexedDBテスト
npm run test:e2e    # Windows Edgeでブラウザ操作テスト
```

ブラウザテストは標準インストール先のEdgeを使います。他のChromium実行ファイルは環境変数 `PLAYWRIGHT_EXECUTABLE_PATH` に指定できます。例: PowerShellで `$env:PLAYWRIGHT_EXECUTABLE_PATH='C:\Program Files\Google\Chrome\Application\chrome.exe'`。テスト用データは合成画像のみで、実研究データは使用・変更しません。

## 使い方

公開アプリ右上の「使い方」から、ブラウザ用の説明ページを別タブで開けます。公開アプリURLの末尾に `help.html` を付けて直接共有することもできます。説明ページは編集ロックを取得しないため、記録画面と同時に開けます。

標準Papillaeは1〜6、a1〜a6、b、c1〜c10、cp、d、x、z、hk1、hk2、os、ot、oiの32項目。Landmarkは眼後端、眼中心、眼前端、AN、上唇上端、上顎前端、開口後端、下顎前端、顎後端、胸鰭上端、胸鰭下端、腹鰭前端、第一背鰭前端の13項目（この順序）。

1. JPG / PNG / TIFFをドロップ、または「画像を追加」で複数登録します。同じ原画像を読み込んだ場合も上書きせず通知します。
2. 左欄で個体ID、side（L/R）、計数者を入力します。sexはM/F/未入力です。種名、採集地、SL/HL、pixel_size_um、備考は任意。未入力の必須情報があっても下書きを保全し、出力時に通知します。
3. 右欄の4グループ・32カテゴリから選び、画像を連続クリックします。各ボタンのキーでも切り替えできます。「計数完了」で確定します。**0個の観察も計数完了を指定**してください。写っていない場合は「観察不可」。
4. Landmarkモードで13項目を記録します。eyeは眼の中心です。「自動で次へ」がONなら記録済み・観察不可・スキップを飛ばして次の未記録へ進みます。OFFでは選択を維持。全13点で完了表示。一部欠測のまま保存できます。
5. 編集モードで点を選び、ドラッグまたはXY欄で移動します。孔器のカテゴリ変更、Deleteで削除も可能。記録済みランドマークの再クリックは編集へ誘導します。点の修正後は孔器カテゴリが計数中に戻るため、確認して再度完了を指定します。
6. ホイールでズーム、Spaceを押しながらドラッグでパン、全体表示でフィット。手のアイコンでパンモードも選択できます。ROIボタンの後に画像上をドラッグするとその部分を表示し、隣のリセットアイコンで解除します。
7. 明度・コントラスト・ガンマ・RGB/R/G/Bを表示だけに適用。記録座標と元ファイルは変わりません。右下の表示設定で点の半径・透明度・色を変更し、選択カテゴリの目のアイコンで表示を切り替えます。
8. 画像の別観察者は「ANNOTATION SESSION」の＋で新規セッションを作り、計数者を入力します。同じ画像の左右を混同しないよう、L/Rは画像ごとに設定してください。

Undo: `Ctrl+Z`。Redo: `Ctrl+Y` / `Ctrl+Shift+Z`。`Esc` は選択解除。入力欄ではブラウザ標準のテキスト編集を優先します。Undoは最大80変更、再起動後は履歴を引き継ぎません。

PCでは1280px以上の画面を推奨。1366×768で32カテゴリ全ボタンをスクロールせず操作できることをテストしています。スマホでは次の専用レイアウトへ自動で切り替わります。

## スマホで使う

同じ公開URLをスマホのブラウザで開きます。別アプリのインストールや別URLは不要です。

1. 下の「画像」から画像一覧・個体情報・観察セッションを開きます。画像を読み込み、個体ID・side・計数者を入力してパネルを閉じます。HEICは事前にJPG/PNGへ変換してください。
2. 下のPapillae／Landmarkとカテゴリ名から観察項目を選びます。
3. 1本指で画像を移動し、2本指で拡大・縮小します。中央の小さな十字に対象を合わせて「十字位置に追加」を押します。「直接タップ」への切り替えも可能です。パン・ピンチ・キャンセル操作は点を追加しません。
4. Papillaeは「完了」で確定します。Landmarkの自動送り・スキップ・観察不可も下のボタンで操作できます。
5. 「編集」で点の近くをタップして選択し、移動先を中央に合わせて「十字へ移動」。編集パネルにはXY入力・1px移動・削除があります。下の矢印でUndo/Redoできます。
6. 右上の「書き出す」でJSON／ZIP／CSV／注釈画像を保存します。生成ファイルがダウンロード先にあることを確認してください。PCとのデータ交換はJSON／完全バックアップZIPで行います。端末間の自動同期はありません。

縦画面では下に操作欄、横画面では右側に操作欄を配置し、画像の表示面積を確保します。カテゴリ・個体情報は必要なときにパネルを開きます。明度などの画像調整は「画像」、点の表示設定はカテゴリ一覧パネル内にあります。ROIの新規指定はPC版で行ってください。

タッチ対応Chromiumのスマホ画面エミュレーションで検証しています。iPhone／Android実機、Safariの操作・ファイル保存画面は未検証です。特に大きな画像はスマホのメモリを消費するため、少数画像に分け、「ローカル保存済み」を確認し、作業の区切りごとにJSON／ZIPを別途保存してください。

## 欠測と合計

| 状態                 | CSVのカテゴリ計数      | 集計               |
| -------------------- | ---------------------- | ------------------ |
| unobserved 未観察    | NA                     | 確定合計に含めない |
| counting 計数中      | 現時点の値（UIでは *） | 暫定小計へ         |
| complete 計数完了    | 0以上の値              | 確定小計へ         |
| unavailable 観察不可 | NA                     | 確定合計に含めない |

`a_total` はa1〜a6、`c_total` はc1〜c10、`papillae_total` は全32項目を対象とします。これらの合計は対象カテゴリが**すべて計数完了**の場合だけ数値です。それ以外はNAで、`*_complete=false`。`*_observed_subtotal` は完了カテゴリの小計、`*_provisional` は計数中カテゴリの小計です。未観察を0として扱いません。ランドマークは独立データで孔器数に含みません。

## 出力形式

「書き出す」メニューから次を選べます。

- **プロジェクトJSON**: 元画像を含む完全保存。個体情報、カテゴリ定義、観察状態、全セッション、全点、SHA-256、サイズ、形式バージョンを保持。
- **CSV 5種 ZIP**: UTF-8 BOM付きCSVをまとめて出力。
- **注釈つきPNG 2種 ZIP**: 「Papillaeのみ」の `*_papillae.png` と「Papillae＋Landmark」の `*_with_landmarks.png` をまとめて出力。個別のPNG出力も選べます。Papillaeはカテゴリ設定の32色、Landmarkは記号・ラベルとも共通の黄色です。現在の画像・セッションの全記録を出力するため、画面上の注釈非表示・カテゴリ非表示には影響されません。明度等の表示調整と点の透明度を反映し、ROIに関係なく元画像全体を元サイズで出力。点サイズは出力時のズームに対応するため、同じ表示倍率で比較してください。
- **完全バックアップZIP**: project.json、5CSV、元ファイル、簡単なREADME。元ファイルは `images/<image_id>/<元ファイル名>`。

CSVの基本識別列は `ID, side, image_id, annotation_session_id, observer`。XYは元画像の左上を原点、右/下を正とする浮動小数点ピクセルです。JPEGのEXIF回転はブラウザ適用後のデコード画像を基準とします。pixel_size_umはメタデータとして記録し、XYを自動で実寸へ変換しません。

| ファイル                 | 1行の単位・主な列                                                                                                                         |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| papillae_counts.csv      | 画像・セッション、32カテゴリの計数、3合計、complete/確定小計/暫定小計、各カテゴリのstatus                                                 |
| papillae_coordinates.csv | 孔器1点、category, point_id, x_px, y_px                                                                                                   |
| papillae_status.csv      | セッション・カテゴリ、observation_status, updated_at, count                                                                               |
| landmarks.csv            | セッション・全13項目、point_id, landmark, landmark_label, x_px, y_px, observation_status, updated_at。未記録もNA行を出力                  |
| specimens.csv            | 登録画像、ID, side, observer, species, locality, SL_mm, HL_mm, sex, pixel_size_um, notes, image_id, image_filename, width, height, sha256 |

sexの未入力・数値任意項目の欠測もNA。ランドマークの状態は `unrecorded`, `recorded`, `unavailable`。CSVは引用符、カンマ、改行に対応し、Excel等の数式実行を防ぐため `= + - @` 等から始まる文字列に先頭アポストロフィを付けます。文字列を完全に復元する交換形式にはJSONを使用してください。

## 復元と共同研究者との共有

「データ読込」でJSONまたは完全バックアップZIPを1つ選択します。空の環境では完全復元。既存データがある場合は追加統合します。原画像のSHA-256と個体情報が一致する画像は照合。同一セッションIDで内容が異なる場合は別セッションとして両方残します。同じバックアップの変更なし再読込はセッションを増やしません。異なるカテゴリ設定の統合はエラーにし、既存データを変更しません。

CSVは画像を含みません。**同じimage_idの画像が登録済みの環境**で、エクスポートした `papillae_status.csv`, `papillae_coordinates.csv`, `landmarks.csv` の3つを同時に選択すると、新規セッションとして座標・状態を復元します。状態の欠落、範囲外、観察状態と座標/計数の不整合は拒否します。counts/specimens CSVは解析・確認用で、CSV読込で個体情報を上書きしません。画像やメタデータを含む正確な再開・交換はJSON/ZIPを使ってください。

カテゴリ設定は下端の「設定保存/読込」で共有できます。`src/config.ts` に初期定義があり、追加カテゴリも同じ4グループに所属させ、一意の英数字キーを設定します。設定の読込は観察記録開始前のみ可能です。標準Landmark IDはeye_posterior, eye, eye_anterior, AN, upper_lip, upper_jaw_anterior, mouth_posterior, lower_jaw_anterior, jaw_posterior, pectoral_upper, pectoral_lower, pelvic_anterior, dorsal_origin。

## 旧標準データからの移行

旧標準の22カテゴリ・9LandmarkのJSON、ZIP、ブラウザ保存データを認識し、新定義へ移行します。既存の孔器点・状態・色、共通Landmarkの点IDと座標を維持し、追加項目は未観察／未記録になります。PN・吻前端・吻後端は別の部位へ置き換えず、各セッションの `retired_landmarks` に元の名前・座標・状態を保全します。画面下部の「以前のLandmark（保全）」で確認でき、JSONと追加CSV `retired_landmarks.csv` に出力します。現在の13点や注釈画像には含めません。ブラウザ保存データは移行前のコピーも同じ保存領域に保全します。独自に変更されたカテゴリ定義は自動変更しません。

従来の32カテゴリ・12Landmarkのデータも自動で13Landmarkへ更新します。第一背鰭前端（dorsal_origin）は保全記録があれば元の座標・点ID・観察状態で復元し、なければ未記録で追加します。移行前の12点版のコピーはブラウザ内に別途保全します。旧9点版から直接移行した場合も第一背鰭前端を維持します。

旧CSVだけを新しい32項目へ直接読み込むことはできません。対応する旧JSON／ZIPを先に復元してから、新形式のCSVを使用してください。

## データの安全性と制約

- 350ms後にIndexedDBへ自動保存します。画面が非表示になる際やpagehide時にも最新変更の保存を試みますが、OSによる即時終了は保証できません。「ローカル保存済み」を確認して終了してください。保存待ち・失敗時は閉じる際に標準警告を表示します。
- ブラウザ、プロファイル、URL（scheme/host/port）が変わると保存領域が変わります。ブラウザのデータ消去やプライベートモード終了で失われるため、**JSON/ZIPを定期的に別の場所へ保存**してください。
- 同じURLは1タブだけで編集します。第2タブは書込をロックし、先のタブを閉じた後に再読込が必要です。
- 元ファイルは変更しません。データの全消去機能はありません。点の削除はUndoできます。
- TIFFはUTIFでデコードできる形式の先頭ページを使用し、複数ページでは通知します。すべてのTIFF圧縮やBigTIFFを保証しません。非対応時は原本を保管してPNGへ変換してください。
- 1ファイル200 MB、デコード4000万画素以下。メモリ/保存容量は端末とブラウザ次第です。大きなプロジェクトは分割してください。自動検出・クラウド同期は含みません。
- ROI、表示調整、スキップ、表示/非表示、点サイズ、不透明度は作業中の設定で、再読込では初期化します。点と観察状態は保存されます。
- 付属 `public/sample.png`、`tests/sample.tif`、`tests/sample-small.jpg` は合成の操作試験画像です。研究データやDiASP実画像ではありません。生成コードは `scripts/make_sample.py`。

## GitHub Pagesで公開

1. このソースをGitHubのリポジトリに登録します。研究画像・バックアップはコミットしないでください。
2. Settings → Pages → Sourceを **GitHub Actions** にします。
3. 付属 `.github/workflows/pages.yml` を実行するか、main/masterへpushします。ワークフローが依存取得・単体テスト・ビルドを実行してdistを公開します。
4. 公開されたURLで起動できます。`base: './'` によりリポジトリ配下のURLにも対応。ホスティング先へ研究画像をアップロードする必要はありません。
