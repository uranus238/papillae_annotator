# Papillae Annotator v1 設計

## 利用者ガイドとタブレット対応の更新

使い方の旧データ移行章を削除し、少数枚ずつの観察・完全バックアップZIPの確認・作業済み画像の削除・保存完了後の再読込・次の画像の読込・解析時のCSV/JSON統合へ置き換える。事前トリミングと原本保管、解像度・Landmark範囲・切り出し座標原点、ROIとの違い、重複集計の回避も記載する。旧データの保全・移行機能自体は維持する。

`useMobileLayout`は幅900px以下または主入力がcoarseの場合にタッチUIを使う。coarse側の幅1180px制限を外し、大型タブレットの横向きにも中央十字とタッチ用操作欄を提供する。通常のPC（fine入力）は従来の幅条件のまま。利用者ガイドとREADMEにタブレット対応と実機未検証の範囲を記載する。

## 選択画像の削除

MetadataPanelの画像一覧で選んだ画像に「選択中の画像を削除」を表示する。Appはブラウザ標準の確認ダイアログに対象画像名・個体ID・side・全観察セッション数・孔器/記録済みLandmark/保全済み旧Landmarkの点数を表示し、承認時だけ`removeImage`を1回commitする。キャンセル・ロック中・処理中は変更しない。

`removeImage`は画像IDで1画像を除き、同じ画像IDを参照する全セッションだけを除く。他画像・他画像のセッション・プロジェクト定義は保持し、同じハッシュの別画像も残す。参照元ファイルにはアクセスしない。画像と関連記録を単一のUndo/Redoで復元/再削除できる。履歴は既存の最大80変更・再読込で消失という制約に従う。現在画像が消えた場合は残る画像を表示し、最後の画像の場合は読込待ち画面へ戻る。選択IDは保持して、直後のUndo時に元の選択画像へ戻れるようにする。

## Papillaeの一括計数完了

`BulkComplete.tsx`をPapillaeパネルに配置する。通常は折り畳み、既存カテゴリボタンの操作を維持する。現在の画像・観察セッションに限って個別、グループ単位、計数中のみ、未完了全体の選択ができる。選択項目と現在個数を一覧で示し、未観察は0個で確定されることを明記する。完了済み・観察不可は選択対象外とし、NAを誤って0へ変更しない。選択はセッション切替・モード切替・パネルの折り畳みで解除し、記録データには保存しない。

`completeCategories`は全対象を検証してから状態だけを一括更新し、孔器座標・Landmark・未選択項目を保持する。対象に不明ID・観察不可があれば操作全体を拒否する。Appでは単一commitにまとめ、1回のUndo/Redoで全選択項目を戻せる。状態変更後のCSV集計と自動保存は既存処理を共有する。PCとスマホで同じ機能を使う。

従来の12点・13点の厳密な標準定義をlegacyConfig.tsへ固定し、既存データ・JSON/ZIP・設定読込時に新順序へ更新する。座標・点ID・観察状態・カテゴリ設定はIDで対応付けて保持し、任意の独自定義は変更しない。旧13点の保存データは`before-landmark-order-update-2026-11-17`に一度だけバックアップし、以前の2種類のバックアップも維持する。

## 2026-11-17 第一背鰭前端の再追加

標準Landmarkの末尾に第一背鰭前端（`dorsal_origin`）を追加し、計13項目とする。PC・スマホ・CSV・JSON・注釈PNG・自動進行は共通定義から参照する。色は他のLandmarkと共通。

既知の32カテゴリ・12Landmark定義を認識して更新する。既存のカテゴリ色・キー・孔器点・状態・Landmarkは保持する。第一背鰭前端がretired_landmarksにあれば点ID・座標・観察状態・更新日時を維持して通常のlandmarksへ復元し、保全欄からは除く。同じ点IDを二重に保持しない。存在しなければ未記録・null座標で追加する。新規点IDはセッションから安定して生成し、未変更の旧JSON再読込でセッションが増えない。旧22カテゴリ・9点版からの直接更新でも第一背鰭前端を維持する。独自の観察項目定義は変更しない。

ブラウザ内の12点データは同一トランザクション内で`before-dorsal-landmark-update-2026-11-17`へ一度だけバックアップしてから更新する。従来の11月15日バックアップも保持する。12点版のJSON/ZIPと記録前の設定ファイル読込にも対応する。CSVだけの旧定義の復元は従来どおり対応するJSON/ZIPを優先する。

## 2026-11-16 スマホ対応

同じURL・永続データ・出力形式を使い、幅900px以下、または粗いポインターで幅1180px以下の場合にスマホ用レイアウトへ切り替える。`useMobileLayout.ts` が画面条件とvisualViewportの高さ変更を監視し、ソフトキーボード・回転・ブラウザバーに追随する。縦画面では下に `MobileControls.tsx`、低い横画面では右に操作欄を配置する。左右パネルは必要時だけ開くシートとなり、フォーカス循環・閉じる操作・背景を備える。Viewerはシートの開閉で作り直さない。safe-areaと16pxの入力欄、44px以上の主要ボタンを使用する。

`touch.ts` は元画像座標への変換と独立したジェスチャー状態を持つ。1本指は8 CSS pxを超えたらパン、2本指は指の中点を基準に拡大・縮小と平行移動を行う。複数指・ドラッグ・キャンセル後にはタップを生成しない。Pointer Captureで領域外へ移動した指も追跡し、解除時に確定する。連続移動はrequestAnimationFrameにまとめ、記録操作では最新のView参照から元画像座標を求める。合成マウスイベントによる二重記録を防ぐ。

標準入力は固定した小さな中央十字への照準＋追加ボタン。「直接タップ」も選択可能。編集では24 CSS px以内の可視点を選択し、中央への移動・1px調整・XY入力・削除を利用する。スマホでKonvaの点ドラッグは使用せず画像移動と区別する。新規ROI指定はPCに限定する。観察項目・確定/欠測・Undo/Redoの意味は共通で、スマホとPCはJSON/ZIPで交換できる。クラウド同期は行わない。

自動保存の350msデバウンスに加え、visibilitychange（hidden）とpagehideで最新変更の保存をキューへ追加する。同じスナップショットの重複保存を抑え、読込失敗・編集ロックの保護を維持する。OSの強制終了前に保存が完了する保証はないため、手動バックアップを引き続き案内する。

## 永続データと識別子

`Project` は `format: papillae-annotator`, `version: 1` を持つ。画像ID、セッションID、点ID、プロジェクトIDはUUID。個体IDとsideを識別子として使って画像やセッションを上書きしない。同一ID/sideに任意の画像、画像に任意の観察者別セッションを持てる。

画像には元バイト列のdata URL、SHA-256、表示用PNG、元のデコード幅高さ、個体情報を保存。セッションには画像への参照、計数者、作成更新日時、孔器点配列、カテゴリ状態、ランドマーク辞書を保存する。observerはセッションの値を座標/集計CSVに使用し、異なる計数者を混同しない。specimensのobserverはその画像の情報欄で最後に入力した計数者を示す。解剖学的表示名とは独立した固定Landmark IDを使う。

座標は左上原点の浮動小数点px。`0 <= x < width`, `0 <= y < height`。ビューは `screen = original * scale + translation`。ROIは元座標でのclipであり、画像座標の原点変更を行わない。表示用キャンバスを変えても記録点を変換しない。JPEGのEXIF回転はブラウザのデコーダー適用後の表示用PNGを座標の基準とする。TIFFは先頭ページのデコード座標を使う。

## 欠測・確定値

状態は `unobserved`, `counting`, `complete`, `unavailable`。初期状態は全て未観察。点がある状態から未観察・観察不可への変更は拒否し、削除を伴わせない。0個の計数完了は有効な観察値。点の追加/移動/削除/カテゴリ変更は関連カテゴリを計数中に戻し、再確認を求める。

完全合計は対象カテゴリが全て完了した場合だけ数値。確定小計は完了カテゴリだけの和、暫定小計は計数中カテゴリだけの和。両者を別出力する。ランドマークは `unrecorded`, `recorded`, `unavailable`。未記録/不可のXYはnull、CSVではNA。記録済みへの再クリックは編集モードへ誘導し、既存点を無断上書きしない。点移動は自動進行を実行しない。

計数の正本は点配列と観察状態で、countは必要時に導出する。CSVにはcountを出力し、JSON内で冗長な計数値との食い違いが起こらないようにする。既存点はReact.memoと安定したイベントハンドラで再描画処理を抑え、画像と注釈は別のKonva Layerに配置する。

ポインター座標の表示はrequestAnimationFrameでまとめ、専用のテキスト要素だけを更新する。通常のマウス移動ではビューアのReact状態を更新せず、注釈配列の再走査・キャンバスの再調整を避ける。ROIドラッグ時のみROI形状を更新する。Papillae入力カーソルは15×15pxの専用SVGを使い、ホットスポットは中央に固定する。左右パネルとヘッダーをコンパクトにし、全体表示の余白を片側16pxに抑えて画像に広く割り当てる。

注釈画像はPapillaeのみ／Papillae＋Landmarkの2種類をPNGで生成し、ZIPで一括、または個別に保存できる。孔器は各点のカテゴリに対応する設定色で描画し、Landmarkの記号・ラベルには共通色 `LANDMARK_COLOR` を使う。出力は現在の画像・セッションの全記録を対象とし、ビューアの一時的な表示/非表示には依存させない。両PNGは同じ表示調整・元画像サイズ・孔器の点サイズ/透明度を使い、Landmarkの有無だけを切り替える。元画像および記録座標は変更しない。

## 保存と安全性

Dexieの単一レコードを350msのデバウンス後に書き込む。書き込みはPromiseキューで直列化し、新しい編集がある間は保存済みと表示しない。保存失敗は画面に表示し、未保存時の終了にブラウザ標準警告を出す。データベース読込失敗時は既存領域への自動保存を停止し、JSON保存を案内する。Web Locksで同じoriginの書込タブを1つに限定。他タブは編集できない。未対応ブラウザも編集をロックする。

JSONは画像を含む完全バックアップ。ロード時に構造、IDの一意性、参照、カテゴリ、状態/座標、範囲、原本SHA-256を検証する。既存プロジェクトへの読み込みは追加統合。同じ画像（ハッシュ・個体情報の一致）は参照を統一し、同じセッションIDで内容が異なる場合は新IDで両方残す。異なるカテゴリ設定の統合は拒否。CSVは登録済みimage_idを参照して新規セッションを作成する。入力不整合は全体を拒否し、部分的に適用しない。

全画像を一度に消去するUIは設けない。選択中の1画像と紐づく全記録の削除は確認付きで実行でき、画像削除・点削除・メタデータ編集はUndo可能（最大80変更）。画像の原本は変更しない。容量上限はブラウザ依存で、ファイル200 MB・デコード4000万画素以下に制限する。大規模プロジェクトは適宜分割する。表示調整、ROI、非表示、半径、不透明度、スキップ、Undo履歴は一時的な作業設定。

## 配布と通信

Viteの静的ビルドでbaseは相対パス。外部フォント、分析、API、クラウド送信なし。起動時のアセットと明示的な検証サンプル以外の通信を必要としない。初回起動のためのHTTPサーバーまたは静的ホスティングを利用する。クラウド同期、画像自動検出、リアルタイム共同編集は実装しない。

技術参照: [Konvaのポインター基準ズーム](https://konvajs.org/docs/sandbox/Zooming_Relative_To_Pointer.html)、[Dexie Reactガイド](https://dexie.org/docs/Tutorial/React)。

## 2026-11-15 観察定義と利用者ガイド

a1〜a6、b、c1〜c10、その他（番号1〜6とcp、d、x、z、hk1、hk2、os、ot、oi）の32カテゴリ。番号1〜6は従来の「その他」グループに追加し、4グループを維持する。数値だけのカテゴリIDも文字列として保存し、CSV列名を変更しない。新しい12Landmarkの並びはconfig.tsに集約する。旧標準の定義はlegacyConfig.tsに保持し、既知の旧標準だけをupgradeObservationDefinitionsで更新する。追加状態は未観察／未記録で、既存点と共通項目の点IDを保持する。削除された4LandmarkはSession.retired_landmarksにラベル・座標・状態を保全する。CSVは旧項目があるときだけretired_landmarks.csvを追加。JSON統合では旧定義を新定義に合わせ、再読込で同じ旧セッションが増えないよう新規の未記録Landmark IDと日時を安定させる。独自設定は変更しない。

ブラウザ内移行はDexieの単一トランザクションで、移行前のprojectをbefore-observation-update-2026-11-15キーへ保全してからcurrentを更新する。JSON/ZIPの入力ファイルは変更しない。

利用者ガイドはhelp.htmlとsrc/HelpPage.tsxの独立したViteエントリー。アプリを閉じずに別タブで参照でき、IndexedDBや編集ロックにはアクセスしない。相対アセットURLによりGitHub Pagesのリポジトリ配下でも動作し、ヘルプ自体のURLを共同研究者へ共有できる。
