# Papillae Annotator v1 設計

## ファイル構成

- `src/config.ts`: 標準32カテゴリ・4グループ・12ランドマークのID、色、キー。
- `src/domain.ts`: バージョン付きデータ型、検証、純粋な更新関数、座標変換、欠測を考慮した集計、追加統合。
- `src/images.ts`: JPG/PNG/TIFFの読み込み、原本ハッシュ、非破壊表示調整。
- `src/Viewer.tsx`: react-konvaの画像/注釈の別Layer、ズーム、パン、ROI、座標編集、PNG。
- `src/MetadataPanel.tsx` / `AnnotationPanel.tsx`: 左右の記録UI。
- `src/useProject.ts` / `db.ts`: Undo/Redo、遅延自動保存、排他的書込。
- `src/io.ts`: CSV、完全JSON、ZIP、厳密な入力検証。
- `tests/`: ドメイン、IndexedDB、実ブラウザでの統合テスト。

## 永続データと識別子

`Project` は `format: papillae-annotator`, `version: 1` を持つ。画像ID、セッションID、点ID、プロジェクトIDはUUID。個体IDとsideを識別子として使って画像やセッションを上書きしない。同一ID/sideに任意の画像、画像に任意の観察者別セッションを持てる。

画像には元バイト列のdata URL、SHA-256、表示用PNG、元のデコード幅高さ、個体情報を保存。セッションには画像への参照、計数者、作成更新日時、孔器点配列、カテゴリ状態、ランドマーク辞書を保存する。observerはセッションの値を座標/集計CSVに使用し、異なる計数者を混同しない。specimensのobserverはその画像の情報欄で最後に入力した計数者を示す。解剖学的表示名とは独立した固定Landmark IDを使う。

座標は左上原点の浮動小数点px。`0 <= x < width`, `0 <= y < height`。ビューは `screen = original * scale + translation`。ROIは元座標でのclipであり、画像座標の原点変更を行わない。表示用キャンバスを変えても記録点を変換しない。JPEGのEXIF回転はブラウザのデコーダー適用後の表示用PNGを座標の基準とする。TIFFは先頭ページのデコード座標を使う。

## 欠測・確定値

状態は `unobserved`, `counting`, `complete`, `unavailable`。初期状態は全て未観察。点がある状態から未観察・観察不可への変更は拒否し、削除を伴わせない。0個の計数完了は有効な観察値。点の追加/移動/削除/カテゴリ変更は関連カテゴリを計数中に戻し、再確認を求める。

完全合計は対象カテゴリが全て完了した場合だけ数値。確定小計は完了カテゴリだけの和、暫定小計は計数中カテゴリだけの和。両者を別出力する。ランドマークは `unrecorded`, `recorded`, `unavailable`。未記録/不可のXYはnull、CSVではNA。記録済みへの再クリックは編集モードへ誘導し、既存点を無断上書きしない。点移動は自動進行を実行しない。

計数の正本は点配列と観察状態で、countは必要時に導出する。CSVにはcountを出力し、JSON内で冗長な計数値との食い違いが起こらないようにする。既存点はReact.memoと安定したイベントハンドラで再描画処理を抑え、画像と注釈は別のKonva Layerに配置する。

ポインター座標の表示はrequestAnimationFrameでまとめ、専用のテキスト要素だけを更新する。通常のマウス移動ではビューアのReact状態を更新せず、注釈配列の再走査・キャンバスの再調整を避ける。ROIドラッグ時のみROI形状を更新する。Papillae入力カーソルは15×15pxの専用SVGを使い、ホットスポットは中央に固定する。左右パネルとヘッダーをコンパクトにし、全体表示の余白を片側16pxに抑えて画像に広く割り当てる。

注釈画像はPapillaeのみ／Papillae＋Landmarkの2種類をPNGで生成し、ZIPで一括、または個別に保存できる。孔器は各点のカテゴリに対応する設定色で描画し、Landmarkの記号・ラベルには共通色 `LANDMARK_COLOR` を使う。出力は現在の画像・セッションの全記録を対象とし、ビューアの一時的な表示/非表示には依存させない。両PNGは同じ表示調整・元画像サイズ・孔器の点サイズ/透明度を使い、Landmarkの有無だけを切り替える。元画像および記録座標は変更しない。

## 保存と安全性

Dexieの単一レコードを350msのデバウンス後に書き込む。書き込みはPromiseキューで直列化し、新しい編集がある間は保存済みと表示しない。保存失敗は画面に表示し、未保存時の終了にブラウザ標準警告を出す。データベース読込失敗時は既存領域への自動保存を停止し、JSON保存を案内する。Web Locksで同じoriginの書込タブを1つに限定。他タブは編集できない。未対応ブラウザも編集をロックする。

JSONは画像を含む完全バックアップ。ロード時に構造、IDの一意性、参照、カテゴリ、状態/座標、範囲、原本SHA-256を検証する。既存プロジェクトへの読み込みは追加統合。同じ画像（ハッシュ・個体情報の一致）は参照を統一し、同じセッションIDで内容が異なる場合は新IDで両方残す。異なるカテゴリ設定の統合は拒否。CSVは登録済みimage_idを参照して新規セッションを作成する。入力不整合は全体を拒否し、部分的に適用しない。

原画像、点、セッションを一括削除するUIは設けない。点削除とメタデータ編集はUndo可能（最大80変更）。画像の原本は変更しない。容量上限はブラウザ依存で、ファイル200 MB・デコード4000万画素以下に制限する。大規模プロジェクトは適宜分割する。表示調整、ROI、非表示、半径、不透明度、スキップ、Undo履歴は一時的な作業設定。

## 配布と通信

Viteの静的ビルドでbaseは相対パス。外部フォント、分析、API、クラウド送信なし。起動時のアセットと明示的な検証サンプル以外の通信を必要としない。初回起動のためのHTTPサーバーまたは静的ホスティングを利用する。クラウド同期、画像自動検出、リアルタイム共同編集は実装しない。

技術参照: [Konvaのポインター基準ズーム](https://konvajs.org/docs/sandbox/Zooming_Relative_To_Pointer.html)、[Dexie Reactガイド](https://dexie.org/docs/Tutorial/React)。

## 2026-11-15 観察定義と利用者ガイド

a1〜a6、b、c1〜c10、その他（番号1〜6とcp、d、x、z、hk1、hk2、os、ot、oi）の32カテゴリ。番号1〜6は従来の「その他」グループに追加し、4グループを維持する。数値だけのカテゴリIDも文字列として保存し、CSV列名を変更しない。新しい12Landmarkの並びはconfig.tsに集約する。旧標準の定義はlegacyConfig.tsに保持し、既知の旧標準だけをupgradeObservationDefinitionsで更新する。追加状態は未観察／未記録で、既存点と共通項目の点IDを保持する。削除された4LandmarkはSession.retired_landmarksにラベル・座標・状態を保全する。CSVは旧項目があるときだけretired_landmarks.csvを追加。JSON統合では旧定義を新定義に合わせ、再読込で同じ旧セッションが増えないよう新規の未記録Landmark IDと日時を安定させる。独自設定は変更しない。

ブラウザ内移行はDexieの単一トランザクションで、移行前のprojectをbefore-observation-update-2026-11-15キーへ保全してからcurrentを更新する。JSON/ZIPの入力ファイルは変更しない。

利用者ガイドはhelp.htmlとsrc/HelpPage.tsxの独立したViteエントリー。アプリを閉じずに別タブで参照でき、IndexedDBや編集ロックにはアクセスしない。相対アセットURLによりGitHub Pagesのリポジトリ配下でも動作し、ヘルプ自体のURLを共同研究者へ共有できる。
